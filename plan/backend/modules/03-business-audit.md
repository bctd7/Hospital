# 业务审计模块

> 状态：Identity 授权审计已有实现基础；其他领域随业务模块接入

## 1. 定位

业务审计是平台支撑业务能力，记录关键事实：谁在什么时间，以什么身份，对哪个对象执行了什么
操作，结果如何。它不能使用普通运行日志替代，也不等同于 Trace。

审计不必立即拆成独立微服务。首期由拥有业务数据的服务在本地事务或可靠 Outbox 链路中写入，
以后只有在统一查询、独立权限、独立保留周期和独立运维边界成立时才评估 Audit Service。

## 2. 首批审计事件

### Identity

- 首位超级管理员初始化；
- 账号角色授予或撤销；
- 医生身份开通；
- 部门调整；
- 账号禁用、恢复或注销审批；
- 管理员按手机号精确查找账号。

### 业务模块

- 跨部门查看敏感患者资料；
- 预约人工调整、取消和资源释放；
- 规划规则发布、停用和方案人工修改；
- 地图或地点版本发布；
- 报告发布、更正、撤回、下载和导出；
- 高风险批量操作和数据导出。

## 3. 通用字段

```text
audit_id
occurred_at
actor_account_id
actor_roles / actor_department_id（必要快照）
action
resource_type / resource_id
target_account_id（如适用）
operation_id / request_id / trace_id
result / reason_code
before_summary / after_summary（仅必要且脱敏）
```

审计不能保存短信验证码、Token、完整手机号、病历正文或不必要的敏感快照。查询审计记录本身也
需要受控权限并产生必要的访问记录。

## 4. 一致性与防篡改

- 权限变更审计与授权事实更新在同一事务内完成；
- 跨服务汇总使用 Outbox，消费者按 `audit_id` 或 `operation_id` 幂等；
- 已提交审计原则上只追加，不原地覆盖；
- 更正通过补充记录表达；
- 保留期、归档、导出和删除策略需结合医院合规要求确认；
- 普通业务管理员不能直接修改或物理删除审计数据。

## 5. 与可观测性的关系

运行日志保存排障上下文，Trace 串联调用，Metrics 反映趋势，审计证明业务事实。它们可以共享
`request_id`、`trace_id` 和稳定事件名，但拥有不同存储、访问权限和保留周期。

## 6. 验收标准

- 高风险操作成功和失败均有审计；
- 可通过 operation/request ID 关联业务请求；
- 授权变更与审计不会出现一边成功一边丢失；
- 审计内容经过数据最小化和脱敏；
- 未授权账号不能查询或修改审计；
- 服务重试不会产生无法区分的重复记录。
