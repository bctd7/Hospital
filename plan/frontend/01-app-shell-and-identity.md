# 应用外壳与身份版本

## 固定导航

小程序固定四个 Tab，页面结构不随功能扩展而增加新的一级入口：

| 序号 | 患者端 | 工作人员端 |
|---:|---|---|
| 1 | 首页 | 首页 |
| 2 | 医生名录 | 人员管理 |
| 3 | 消息 | 消息 |
| 4 | 我的 | 我的 |

Tab 路由相同，标题和页面内容根据 `appVariant` 切换。所有页面必须先恢复有效 Session；开发、测试和正式构建
都不提供绕过登录的身份。

## 身份规则

- 普通患者只能使用患者端；
- 医生和超级管理员默认可使用工作人员端，也保留全部患者基础能力；
- 工作人员主动切换到患者端后，预约记录的患者仍是当前账号自身；
- 切换只改变 UI 和调用的业务入口，不修改后端角色、权限或科室；
- 前端权限判断只控制可见性，后端仍按 Token、permission 和科室范围鉴权。

## 首页

首页卡片是静态编排，不是业务 Mock。检查项目、预约、报告和消息等目标页面读取真实接口。患者端与工作人员
端保持同一视觉结构，只替换已经确认的业务入口：

- 患者诊前：我的预约、就诊人管理；
- 工作人员诊前：科室预约、就诊人管理；
- 患者诊后：检查记录，并从有已发布报告的记录打开只读报告；
- 工作人员诊后：检查记录；
- 首页不展示诊中服务分组；缴费、医保电子凭证、电子票据和住院病案复印在没有真实闭环前不提供占位入口。

首页不增加第二个工作台，也不把消息管理塞进“我的”。“我的”仅保留真实可用入口，不展示尚未实现的设置页。

## 会话与错误

API Client 统一附加 Bearer Token，并把并发 401 合并为一次 Refresh。刷新失败或授权版本失效后清理本地会话
并返回登录页。业务页面展示后端返回的稳定错误含义，不能只在控制台留下 400/409/500。

TabBar 徽标只能在 Tab 页面上下文更新；非 Tab 页面只刷新内存中的未读数，避免调用
`setTabBarBadge:fail not TabBar page`。
