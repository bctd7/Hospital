# 小程序产品前端稳定化与重构计划

> 状态：执行中。
> 本次重构在独立分支 `codex/miniapp-product-refactor` 进行。产品形态已经确定，允许调整前端内部组织；页面入口、
> 布局、配色、文案含义、现有功能和后端业务边界不得因重构发生变化。

## 一、目标与硬约束

本次工作同时解决已经确认的智能导诊缺陷，并把当前小程序整理成可以继续维护的稳定结构。

- 页面只负责组合展示与接收用户操作，不继续堆叠请求并发、业务推导、缓存恢复和错误翻译；
- 同一种加载、空态、错误态、提交态和页面恢复逻辑只保留一套实现；
- 异步初始化必须有明确阶段，不能在依赖数据尚未就绪时提前生成方案或绘制地图；
- 后到的旧请求不能覆盖新选择产生的结果；重复点击不能产生重复请求；
- 原生地图等重型组件只在数据稳定后挂载，弹层和路线阶段切换不能反复销毁、重建地图；
- API 的正常业务无结果、并发冲突、鉴权失败和服务异常必须分别表达；
- 不借重构恢复已经删除的入口、占位功能、医生资源关系或 Mock 登录路径；
- 不修改已确定的患者端/工作人员端身份视图，不改变首页与四个 Tab 的产品结构。

## 三、已经确认必须修复的问题

1. 模型可能返回 `null` 数组，配置页直接读取 `.length` 后崩溃并长期停留在“解析中”；
2. 模型解析较慢时缺少稳定的超时、降级和人工确认反馈；结构化准备规则必须可以删除、补充和修改；
3. “直接顺序”的标签和选项不能让工作人员一眼理解谁先做、谁后做；
4. 生成方案可能在项目、日期或已有预约尚未全部就绪时提前触发，页面偶发闪烁；
5. 备选方案与优先方案完全一致时仍重复展示；没有实质差异时不得强行生成备选；
6. 无可行方案属于正常业务结果，页面不能以裸 `409 Conflict` 或笼统系统错误呈现；
7. 从当日方案导入地图时，本地快照恢复、进度刷新和地图计算互相触发，页面偶发反复闪烁；
8. 公交路线调用返回 `internal error`，而步行和驾车正常；必须修复供应商响应解析和错误分类；
9. 页面重新进入、切换交通方式或切换路线阶段时，旧请求不能覆盖当前选择；
10. 所有修复必须覆盖开发版和发布版构建，不得依赖手工等待或偶然请求顺序。

## 四、目标前端分层

```text
pages/                 页面布局、路由参数和用户事件
components/            无业务所有权的可复用展示与输入组件
features/              按产品能力组织的页面状态和组合逻辑
  appointment/
  identity/
  management/
  guidance/
services/              跨页面业务读取与身份视图编排
api/                   HTTP 契约、鉴权、超时和统一错误对象
stores/                会话等真正跨页面且需要长期存在的状态
utils/                 无副作用的格式化、比较和存储编解码
```

`features/` 中的组合函数负责一次页面会话内的异步生命周期，例如初始化、取消旧结果、请求去重、表单草稿、地图
阶段恢复；它们不能隐藏后端业务规则，也不能把 Appointment、Identity 或 Guidance 的事实复制到前端。

## 五、实施顺序

### 阶段一：建立行为基线

- 为关键页面补充状态转换和 API 调用测试；
- 固定患者/工作人员首页入口、资源管理双栏、预约状态和智能导诊页面快照式事实；
- 记录当前请求次数，防止重构后重复加载。

### 阶段二：优先修复智能导诊

- 后端统一模型候选结构，任何数组字段均返回空数组而不是 `null`；
- 前端配置草稿支持受约束编辑，并明确模型、默认解析和人工修改来源；
- 方案生成使用单一请求会话，依赖数据就绪后才允许执行；
- 后端按预约分配事实生成方案签名并去重，前端再做防御性去重；
- “无方案”返回稳定业务结果；真正的方案过期或容量变化继续使用冲突反馈；
- 地图页面把“恢复行程、读取检查进度、选择当前阶段、计算单段路线”串成单向状态流；
- 公交、步行、驾车使用相同的供应商错误契约和可空字段解析规则。

### 阶段三：提取全产品复用逻辑

- 提取加载/提交状态、Latest Request、分页和表单草稿组合函数；
- 把超长页面中的业务状态迁入对应 `features/`，模板和样式原样保留；
- 先处理行数和职责最高的登录、资源管理、房间/项目详情、人员管理和预约页；
- 小页面只在确有重复时迁移，避免为了目录整齐制造空壳文件。

### 阶段四：完整回归

- `vue-tsc`、全部 Vitest、Guidance Go 测试；
- 开发版与发布版微信小程序构建；
- 真实后端验证模型解析、唯一方案、无方案、地图导入、三种交通方式和阶段切换；
- 检查请求次数、控制台错误、页面闪烁和旧数据覆盖；
- 更新本文和智能导诊文档，删除完成后失效的临时说明。

## 六、完成标准

- 现有 24 个页面路由和四个 Tab 不减少、不新增，首页布局与身份差异不变；
- 关键页面不再同时承担 API 细节、业务推导、缓存恢复和完整渲染；
- 模型返回空值、超时或非法结果时页面可恢复并允许人工确认；
- 方案生成和地图导入不闪烁、不重复请求、不显示重复备选；
- 无方案提供明确正常反馈，公交路线可以和步行、驾车一样稳定显示；
- 预约、科室管理、报告、消息、登录和身份切换现有测试全部通过；
- 微信小程序开发版与发布版均可编译，控制台没有本次重构引入的新错误。
