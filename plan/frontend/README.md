小程序已经接入 Identity 与 Appointment 真实接口。首页本身是静态服务入口编排，目标页面再加载真实业务
数据；仓库不再保留预约 Mock、演示账号或免登录测试路径。

## 当前基线

- uni-app、Vue 3、TypeScript 和 Vite；
- 手机号验证码登录，每次联调均使用真实会话；
- 患者端与工作人员端共用账号和 Token，工作人员可以主动切换到患者端；
- 页面统一通过 API Client、服务层和 Session Store 调用，不直接散落 `uni.request`；
- 开发版和发布版产物隔离，上传只使用 `dist/build/mp-weixin`；
- 首页结构保持稳定，只展示已经形成真实业务闭环的入口；未规划服务不放置“建设中”占位按钮。

## 页面事实

| 一级位置 | 患者端 | 工作人员端 |
|---|---|---|
| 首页 | 检查项目、智能导诊、我的预约、检查记录 | 检查资源管理、导诊管理、科室预约、检查记录 |
| 第二 Tab | 医生名录 | 人员管理 |
| 第三 Tab | 本人预约与报告消息 | 当前科室预约与报告提醒 |
| 我的 | 本人资料、就诊人、我的预约、我的关注 | 保持个人视角，并提供患者端/工作人员端切换 |

“我的”中的“我的预约”始终是当前账号自己的患者预约，不因工作人员身份变成科室预约；科室预约和检查记录
位于工作人员首页。“我的”不展示尚未实现的设置项；退出或账号设置重新进入产品范围时必须先明确真实交互。

首页不展示诊中服务分组。诊后服务在患者端和工作人员端都只保留“检查记录”：患者查看自己的已完成和未到场记录，
有已发布报告的记录可以继续打开只读报告；工作人员查看本科室终态记录并继续处理报告待完成事项。缴费、医保
电子凭证、电子票据和住院病案复印不以占位功能出现。

智能导诊已经接入多项目与非连续日期选择、少量方案生成、整组预约确认、当日检查阶段和地图导入；诊前服务的
“检查导航”继续支持独立 A、B 两点选取与微信地图展示。现有“我的预约”保持不变。工作人员端“导诊管理”已按
“新建/编辑项目、配置前后关系、智能解析准备要求”三步实现；房间资源页只关联已有项目，不再直接创建项目。
