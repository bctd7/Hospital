# 组织目录消费方案

> 状态：首期前后端真实 HTTP 联调完成
>
> 本文只规定页面加载、缓存和失效策略。准确路径、字段、鉴权和错误以 `contracts/api/` 与生成的
> `docs/api/openapi.json` 为准。

## 1. 当前范围

首期目录为“唯一医院—多个院区—院区直属科室—有效医生”。医院根节点只读，超级管理员维护院区和
科室；患者和医生读取相同的有效目录。前端不硬编码医院、院区、科室和医生，也不根据名称推断层级。

运行时只使用真实 HTTP Adapter，不保留 Mock 数据源或演示账号。

## 2. 加载策略

1. 进入页面先读取组织上下文和有效院区；
2. 选择院区后加载其直属科室；
3. 选择科室后分页加载有效医生；
4. 快速切换使用请求序号丢弃迟到响应；
5. 没有院区、科室或医生时显示真实空状态。

不得首屏一次加载整棵组织树和全部医生。所有关联、列表 key 和写操作使用稳定 ID，名称只用于展示。

## 3. 权限和管理交互

- 普通用户和医生只读，不挂载组织写操作；
- 超级管理员入口按 permission 展示，后端仍对每次请求最终鉴权；
- 医院根节点不提供编辑、停用或切换；
- 首期科室必须直属院区，不提供子科室入口；
- 停用和恢复是状态变化，不视为物理删除；
- 组织写请求使用服务端版本做乐观锁，并使用 `operation_id` 保证幂等。

医生开通、调岗、撤销身份和账号启停属于用户详情，不放在目录列表行。

## 4. 缓存失效

- 组织上下文按应用版本短期缓存；
- 科室列表按 `campus_id` 缓存；
- 医生列表按 `department_id + page` 缓存；
- 新增、移动、停用或恢复科室后，失效受影响院区缓存；
- 开通、调岗或撤销医生后，失效受影响科室医生列表与计数；
- 版本冲突、资源停用或权限变化时重新读取服务端事实，不把本地缓存当作写入结果。

## 5. 验收边界

- 各身份看到一致的有效公共目录，只有授权管理员看到写入口；
- 多个院区存在同名科室时仍按稳定 ID 正确区分；
- 快速切换、分页、刷新和并发修改不会串数据；
- 响应和页面不暴露完整手机号、OpenID、Token 或管理员内部字段。
