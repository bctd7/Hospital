# 管理员用户接口消费方案

> 状态：首期前后端真实 HTTP 联调完成
>
> 本文只规定管理员页面的查询、操作和刷新策略。准确路径、字段、鉴权和错误以 `contracts/api/` 与
> 生成的 `docs/api/openapi.json` 为准。

## 1. 使用边界

本组能力仅服务超级管理员用户管理页。前端路由和按钮按身份、permission 与服务端返回的可用操作控制；
App API 和 Identity 仍完成最终鉴权，隐藏页面入口不是安全边界。

当前全链路已覆盖：账号分页与详情、完整手机号精确查找、昵称或医生名称候选查询、开通医生、编辑
医生资料、调岗、撤销医生身份、禁用账号和恢复账号。

## 2. 查询策略

- 分页和筛选由后端执行，不把全部账号拉到前端过滤；
- 完整手机号走精确查询，昵称和医生显示名称只返回允许重名的分页候选；
- 管理员进入详情再次核对脱敏手机号、身份、科室和状态；
- 所有写操作以稳定 `account_id` 为目标，手机号和昵称只用于定位候选；
- 列表和详情不展示 Token、验证码、完整审计记录或内部密钥。

## 3. 写操作策略

- 开通医生、编辑资料、调岗和撤销身份使用授权管理权限；
- 账号禁用和恢复使用账号管理权限；
- 每次写操作携带 `operation_id`，网络重试不得制造重复业务结果；
- 请求携带 `management_version`，冲突时重新读取详情并由管理员再次确认；
- 调岗、撤销和账号状态变化提升授权版本，旧会话按统一会话规则失效；
- 撤销医生身份保留普通账号和历史记录；禁用账号不等于撤销医生身份；
- 首期不通过该页面授予、撤销或禁用超级管理员。

## 4. 页面刷新

- 用户列表按筛选条件和页码短期缓存，进入详情时读取最新事实；
- 写入成功后失效目标详情、相关列表和受影响科室医生目录；
- `401` 进入统一单次刷新；`403` 退出管理页面；版本冲突不自动覆盖；
- 高风险操作等待服务端成功并二次确认，不进行破坏性乐观更新。

## 5. 隐私与验收

完整手机号只在精确搜索请求中短暂使用，不进入普通日志和 Toast。查询敏感详情及所有管理写操作由
后端记录审计；普通分页不逐行制造审计噪声。

验收必须覆盖普通用户/医生越权、重复点击、并发管理员修改、调岗后的缓存失效、撤销与账号禁用语义
分离，以及所有列表数据来自真实后端。
