# 应用外壳与身份版本

> 状态：基础外壳和版本切换已实现，业务内容待接入

## 1. 固定一级页面

| 顺序 | 患者端 | 工作人员端 | 路由 |
|---|---|---|---|
| 1 | 首页 | 工作台 | `pages/home/index` |
| 2 | 挂号 | 部门管理 | `pages/registration/index` |
| 3 | 消息 | 消息 | `pages/messages/index` |
| 4 | 我的 | 我的 | `pages/profile/index` |

当前继续使用标准 TabBar 和同一组页面路由，不创建两份小程序工程。患者端与工作人员端通过
`appVariant` 切换文案和内容组件，从而复用布局、会话、请求层和公共组件。

首版固定保留四个 Tab，不因超级管理员身份动态增加第五项。“用户管理”是超级管理员专属二级页，
从“部门管理”右上角进入；这样继续使用原生 TabBar，不引入自定义 TabBar 的状态同步和兼容成本。

## 2. 应用版本规则

```text
普通账号
  -> available = [patient]

department_doctor / super_admin
  -> available = [patient, staff]
  -> 登录默认进入 staff
  -> 可以在“我的”中切换到 patient
```

选择结果是当前设备的界面偏好，不改变账号类型、角色、部门或 Token 权限。恢复会话时校验本地
选择；工作人员角色被撤销后回退患者端。

医生和超级管理员共用工作人员框架。未来超级管理员多出的身份录入页面按 permission 添加菜单，
而不是复制管理员版小程序或另建 Web 后台；医生看不到没有权限的入口。

## 3. 当前页面状态

- 患者首页、挂号、消息显示真实空状态；
- 工作台和工作人员消息暂时显示建设中，不伪造数据；
- 工作人员“部门管理”按[独立页面文档](./04-department-management.md)接入后端动态数据；
- 超级管理员从部门管理页进入[用户管理二级页](./05-admin-user-management.md)，医生不显示入口；
- “我的”使用同一资料头部与菜单组件，并显示可用版本切换入口；
- 二级页面使用 `navigateTo`，Tab 页面使用 `switchTab`；
- 跳转具有互斥保护和失败反馈，避免连续点击造成并发跳转。

工作人员业务真正开始后，优先按页面内部组件和权限菜单扩展；只有导航结构确认无法复用时才
评估自定义 TabBar 或独立页面树。

## 4. 后端关系

页面外壳和 TabBar 不需要后端动态下发路由。后端只返回稳定的角色和权限能力，前端根据已发布
页面决定可见入口。不得允许后端下发任意客户端路由。

## 5. 验收标准

- 四个 Tab 页面切换稳定且无重复跳转；
- 普通用户不能选择工作人员端；
- 医生和超级管理员可进入同一工作人员框架；
- 工作人员仍可使用患者端本人功能；
- 超管专属入口未来按权限出现，医生不会看到；
- 修改本地 `appVariant` 不能扩大后端权限；
- 空页面不展示模拟医疗或业务数据。
