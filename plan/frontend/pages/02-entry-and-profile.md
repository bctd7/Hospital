# 登录入口与个人中心页面

> 状态：当前页面与服务端昵称同步均已实现

## 1. 登录入口

入口页包含：

- 可选微信头像；
- 可选昵称；
- 手机号；
- 短信验证码；
- 获取验证码与“手机号登录 / 注册”按钮。

头像和昵称只作为展示资料，不参与认证，也不代表真实姓名。手机号验证码成功后建立 Hospital
会话，读取 `/auth/me`，再根据 `appVariant` 进入患者端或工作人员端。认证失败时停留入口页并
显示可理解的错误，不伪装登录成功。

## 2. “我的”页面

资料头部展示头像和昵称，缺省值为默认头像与“微信用户”。患者端当前包含：

1. 就诊人管理；
2. 我的预约；
3. 我的关注；
4. 设置。

消息统一从第三个 Tab 进入，“我的”不再提供重复的消息管理入口。

具有工作人员角色时，页面额外显示“患者端 / 工作人员端”切换。工作人员专属业务菜单尚未
确定；以后根据 permissions 增加通用工作人员入口和超级管理员专属身份录入入口。

## 3. 展示资料

当前展示资料由 Identity 保存；用户在就诊人管理页面确认昵称时同步到后端，供本人在不同手机登录
同一微信小程序时显示，并供超级管理员备选搜索。本地 Storage 只作为按
`account_id` 隔离的界面缓存，不与 Token Storage 混合：

- 更新头像或昵称不修改 `account_id`；
- 昵称允许重复，不参与登录、授权或实名判断；
- 退出登录可以保留当前账号缓存，但切换账号不能展示上一个账号的昵称；
- 页面不得展示验证码、完整 Token 或服务端 Secret；
- 医疗实名姓名以后由 Patient 模块单独保存，不能直接复用昵称。

## 4. 验收标准

- 验证码发送期间按钮防重复并显示倒计时；
- 登录按钮防止重复提交；
- 登录成功按身份进入正确应用版本；
- 就诊人管理保存昵称后同步到后端，失败时保留编辑内容并允许重试；
- “我的”菜单只包含当前确认入口；
- 连续点击菜单不会产生多个 `navigateTo`；
- 页面内容适配安全区且不被 TabBar 遮挡。
