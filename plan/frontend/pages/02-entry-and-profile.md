# 登录入口与个人中心页面

> 状态：当前页面实现说明

## 1. 登录入口

入口页包含：

- 可选微信头像；
- 可选昵称；
- 手机号；
- 短信验证码；
- 获取验证码与“手机号登录 / 注册”按钮。

头像和昵称只作为展示资料，不参与认证，也不代表真实姓名。手机号验证码成功后建立 Hospital
会话，读取 `/auth/me`，再根据 `appVariant` 进入患者端或工作人员端。认证失败时停留入口页并
显示可理解的错误，不伪装登录成功。

## 2. “我的”页面

资料头部展示本地头像和昵称，缺省值为默认头像与“微信用户”。患者端当前包含：

1. 就诊人管理；
2. 我的预约；
3. 我的关注；
4. 设置；
5. 消息管理。

当前只保留以上五个入口；二级业务尚未接入时只显示空状态。

具有工作人员角色时，页面额外显示“患者端 / 工作人员端”切换。工作人员专属业务菜单尚未
确定；以后根据 permissions 增加通用工作人员入口和超级管理员专属身份录入入口。

## 3. 本地展示资料

展示资料使用独立本地缓存，不与 Token Storage 混合：

- 更新头像或昵称不修改 `account_id`；
- 退出登录可以保留展示资料；
- 页面不得展示 OpenID、验证码、完整 Token 或服务端 Secret；
- 医疗实名姓名以后由 Patient 模块单独保存，不能直接复用昵称。

## 4. 验收标准

- 验证码发送期间按钮防重复并显示倒计时；
- 登录按钮防止重复提交；
- 登录成功按身份进入正确应用版本；
- “我的”菜单只包含当前确认入口；
- 连续点击菜单不会产生多个 `navigateTo`；
- 页面内容适配安全区且不被 TabBar 遮挡。
