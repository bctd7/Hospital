# 本人就诊信息页面

> 状态：页面骨架已实现；Patient 数据模型和接口尚未实现

## 1. 首版范围

首版一个账号只管理本人，不实现父母、子女或其他家庭成员。当前页面展示：

- 头像；
- 用户名（展示资料，不是医疗实名姓名）；
- 已验证登录手机号的脱敏值；
- 安全说明；
- 退出登录。

页面不存在“启用/停用本人就诊信息”状态开关，也不承担患者端与工作人员端的身份切换。

## 2. 医疗数据边界

PNVS 验证只证明用户控制手机号。严禁通过手机号或“姓名 + 手机号”自动查询医院既有患者、
预约、病历或报告。首版业务数据必须沿稳定内部关系授权：

```text
Token.account_id
  -> patient_profile_id
      -> appointment_id
          -> examination_id
              -> report_id
```

只有目标数据的 `patient_profile_id` 与当前账号已绑定档案一致时才能访问。历史医院数据接入需要
患者主索引匹配、线下核验或更强认证方案。

## 3. 待实现后端

Identity 已负责账号、已验证手机号和会话，但当前没有 Patient 数据结构。预约模块开始前需要
明确采用 `account_id` 还是一对一 `patient_profile_id`；若保存姓名等本人资料，建议提供：

```text
GET /api/v1/patients/me
PUT /api/v1/patients/me
```

后端统一计算资料是否完整，前端不能仅凭本地昵称自行显示“基础认证完成”。

## 4. 验收标准

- 页面不出现家庭成员、默认就诊人或状态开关；
- 手机号只读且脱敏，不提供登录后覆盖入口；
- 退出清理会话但不删除账号和医疗业务数据；
- 不能凭手机号读取其他患者数据；
- 医生或超级管理员切到患者端时，只能访问自己的本人档案。
