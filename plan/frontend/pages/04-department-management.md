# 工作人员部门管理

> 状态：待实现
>
> 适用身份：`department_doctor`、`super_admin`

## 1. 页面目标

医生和超级管理员共用界面的第二个 Tab 由“业务管理”更名为“部门管理”，继续复用
`pages/registration/index` 路由。页面用于查看部门及部门内医生，医生和超级管理员使用同一套
布局与列表组件。医生只读；超级管理员可以维护部门，并从本页进入独立的“用户管理”页面。

前端展示文案统一使用“部门”；后端 `department` 组织单元在当前医疗场景中表示科室。二者使用同一
稳定 `department_id`，不维护两套主数据。

所有科室、医生、身份状态和数量都必须来自后端接口并动态渲染。页面组件内不得维护硬编码的
部门或医生数组；开发期如需演示，只能通过可替换的 mock API 适配层提供，并明确限制在
`local/test` 环境。具体调用见[部门目录与医生管理接口](../api/02-department-directory-and-management.md)。

## 2. 页面布局

```text
┌────────── 部门管理 ──────────┐
│ 左侧部门列       │ 右侧医生列表 │
│ 放射科           │ 张医生       │
│ 检验科           │ 李医生       │
│ 超声医学科       │ ...          │
└─────────────────────────────┘
```

- 左侧约占页面宽度的 34%，独立纵向滚动，显示部门名称、选中态和可选的医生数量；
- 右侧占剩余宽度，顶部显示当前部门名称和人数，下面显示该部门医生；
- 部门列表首次成功返回后，优先选择当前医生唯一所属部门；不存在时选择第一个有效部门；
- 切换部门只更新右侧列表，不发生页面跳转；
- 小程序窄屏仍保持左右结构，名称过长时省略并提供可访问的完整名称；
- 列表没有数据时显示真实空状态，不生成占位部门或医生。

## 3. 身份与权限

### 3.1 医生

- 可以查看后端返回的有效部门；
- 可以切换部门并查看部门内有效医生；
- 不显示新增、编辑、停用、移出等入口；
- 不通过手势、长按或隐藏路由提供写操作；
- 只读目录是预约也会使用的公共接口，不要求医生身份；医生在本页面同样只能读取，不能因此获得
  管理权限。

### 3.2 超级管理员

在只读能力之上，根据 Principal 中的权限显示：

| 能力 | 前端判定 | 页面操作 |
|---|---|---|
| 维护部门 | `identity.department.manage` | 新增、编辑、停用和恢复部门 |
| 进入用户管理 | `super_admin` 且具有 `identity.authorization.manage` 或 `identity.account.manage` | 导航栏右上角显示“用户管理”入口 |

前端权限只决定按钮是否显示；后端必须对每次写请求重新鉴权。接口返回 `403` 时刷新 Principal，
撤下已失效操作入口并提示权限已变化。

## 4. 交互设计

### 4.1 加载与选择

1. 页面进入或会话身份变化时请求部门列表；
2. 按“上次选择且仍有效的部门 -> 当前医生所属部门 -> 第一个有效部门”确定选中项；
3. 携带选中部门 ID 请求医生列表；
4. 用户切换部门时复用未过期缓存，同时在后台按需刷新；
5. 使用请求序号或取消标记丢弃迟到响应，避免快速切换后显示错部门医生。

不得在进入页面时一次性预加载全部部门的全部医生。医生列表按部门请求并支持分页，防止机构
规模扩大后首屏变慢。

### 4.2 部门操作

- “新增部门”打开表单，成功后重新获取部门列表并选中新部门；
- 左侧始终只展示科室；当前只有一个医院，如果存在多个院区，新增/编辑表单单独选择所属院区，
  默认继承当前科室的上级范围；
- “编辑部门”只提交发生变化的字段；
- 页面文案可使用“删除部门”，但确认框必须说明实际结果是停用，历史数据不会删除；
- 有有效子部门或有效医生任职时，后端拒绝停用，前端展示可执行的处理建议；
- 公共科室列表只展示有效数据；超级管理员通过单独的“已停用科室”入口调用管理员查询并执行恢复；
- 写请求进行中锁定对应按钮，成功前不做破坏性乐观更新。

### 4.3 医生列表与用户管理入口

- 医生列表不排列“调岗”“撤销身份”“禁用账号”等操作按钮，避免手机窄屏拥挤和误触；
- 点击医生头像、姓名或整行进入只读医生资料页；医生和超级管理员看到相同的公开资料；
- 超级管理员在页面导航栏右上角看到唯一的“用户管理”入口，进入独立二级页面；
- 医生身份和账号状态操作统一在用户详情页完成，不通过滑动、长按或列表行内按钮触发；
- 用户管理页面规范见[超级管理员用户管理](./05-admin-user-management.md)。

## 5. 数据和组件边界

建议拆分：

```text
DepartmentManagementPage
├── AdminUserManagementEntry         // 导航栏，仅超级管理员有权限时挂载
├── DepartmentSidebar
│   ├── DepartmentListItem
│   └── DepartmentEditorDialog       // 仅有权限时挂载
└── DepartmentDoctorPanel
    └── DoctorListItem
```

- 页面容器负责接口调用、选中部门、分页、缓存失效和错误恢复；
- 展示组件只接收 props/emit，不直接调用 `uni.request`；
- 所有请求继续经过统一 API client 和会话刷新逻辑；
- 列表只使用稳定 `department_id` 和 `doctor_id` 作为 key，不以科室名称或医生名称作为标识；
- 医生列表默认不展示完整手机号等敏感信息。

## 6. 页面状态

必须覆盖以下状态：

- 部门首屏加载、医生列表局部加载；
- 无部门、选中部门无医生；
- 部门加载失败、医生加载失败及局部重试；
- 快速切换部门时旧响应被丢弃；
- 写操作提交中、成功、校验失败、版本冲突和无权限；
- 当前选中部门被其他管理员停用后，刷新并自动选择下一个有效部门；
- 网络恢复后重新拉取，不把旧缓存误认为写入成功。

## 7. 验收标准

- 工作人员端第二个 Tab 显示“部门管理”，患者端仍显示“挂号”；
- 左侧部门和右侧医生全部来自后端，代码中不存在业务演示数组；
- 医生能查看和切换部门，但看不到也无法调用管理操作；
- 超级管理员按权限新增、编辑、停用部门，并从独立用户管理页维护医生归属和身份；
- 切换部门时不会出现上一个部门的迟到数据覆盖当前列表；
- 用户管理页中的调岗、撤销医生身份、禁用账号具有不同提示和接口语义；
- 停用部门或用户管理页调整医生后相关缓存失效，页面以服务端最新结果为准；
- 医生列表中不出现身份和账号操作按钮；超级管理员可从右上角进入独立用户管理页；
- 空状态、失败重试、分页和权限变化均可验证。
