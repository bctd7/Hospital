# 超级管理员用户管理

> 状态：待实现
>
> 适用身份：仅 `super_admin`

## 1. 页面定位

用户管理是超级管理员专属的二级页面，用于查询账号并完成医生身份、所属科室和账号状态操作。
它不加入底部 TabBar，也不与医生共用展示入口；工作人员端继续保持“工作台、部门管理、消息、
我的”四个固定 Tab。

建议放入管理员分包：

```text
pages/admin/users/index       // 用户列表
pages/admin/users/detail      // 用户详情与操作
```

入口位于“部门管理”导航栏右上角。前端进入路由前检查 `super_admin` 身份和管理权限；页面加载时仍由
后端完成最终鉴权，不能依赖隐藏入口保护接口。

## 2. 用户列表

```text
┌──────────── 用户管理 ────────────┐
│ 搜索医生姓名或完整手机号           │
│ 全部｜普通用户｜医生｜已禁用       │
├─────────────────────────────────┤
│ 头像  张三                        │
│       普通用户 · 正常              │
├─────────────────────────────────┤
│ 头像  李医生                      │
│       医生 · 放射科 · 正常         │
└─────────────────────────────────┘
```

- 列表由后端分页返回，默认每页 20 条，不一次性加载全部账号；
- 支持按账号身份、账号状态和科室筛选；
- 手机号只支持管理员输入完整号码精确查询，列表仅显示脱敏值；
- 姓名搜索首期只检索医生显示名称；普通账号通过完整手机号精确查找；
- 每行只展示头像、名称、脱敏手机号、身份、所属科室和账号状态；
- 普通账号没有可展示名称时，以脱敏手机号作为标题兜底；
- 列表行不放置调岗、撤销或禁用按钮，点击整行进入用户详情；
- 列表数据完全来自后端，前端不维护固定用户或医生清单。

## 3. 用户详情与操作

详情页先展示账号事实，再根据账号当前状态和 Principal permission 生成操作区：

| 当前状态 | 可见操作 | 所需权限 |
|---|---|---|
| 普通用户、账号正常 | 开通为医生并选择唯一所属科室 | `identity.authorization.manage` |
| 医生、账号正常 | 编辑公开资料、调整所属科室、撤销医生身份 | `identity.authorization.manage` |
| 普通用户或医生、账号正常 | 禁用账号 | `identity.account.manage` |
| 账号已禁用 | 恢复账号 | `identity.account.manage` |
| 超级管理员 | 首版只读，不提供角色撤销或账号禁用 | 无写入口 |

首版不在该页面授予或撤销 `super_admin`。最后一个可用超级管理员必须由后端永久保护，即使未来增加
管理入口也不能被普通禁用流程处理。

### 3.1 开通医生

- 选择一个后端返回的有效科室；
- 填写工作人员显示名称、可选工号、头像 URL 和擅长描述；
- 明确提示“开通医生不会移除其普通用户能力”；
- 成功后刷新详情和目标科室医生目录。

### 3.2 调整所属科室

- 弹窗展示“原科室 -> 目标科室”，目标只能从有效科室接口选择；
- 首版一个医生只能属于一个科室，提交为一次原子调岗；
- 成功后使原科室、目标科室医生缓存失效；
- 不迁移或改写历史预约、报告及审计记录中的科室快照。

### 3.3 撤销医生身份

- 使用红色危险操作，并进行独立二次确认；
- 确认内容说明：退出工作人员端、保留普通用户账号、保留历史业务记录；
- 成功后撤销医生相关会话，刷新详情和原科室医生目录；
- 不把撤销身份描述为删除用户。

### 3.4 禁用与恢复账号

- 禁用属于账号安全操作，与撤销医生身份分开；
- 确认内容说明患者端和工作人员端都将无法继续登录；
- 禁用成功后撤销全部 Refresh Session，并将列表状态更新为“已禁用”；
- 禁用医生账号保留医生身份和所属科室，恢复后仍是医生；
- 如果医生身份在禁用前后被单独撤销，恢复登录能力不会自动重新开通医生；
- 所有操作均等待后端成功响应，不进行破坏性乐观更新。

## 4. 组件与状态边界

```text
AdminUserListPage
├── UserSearchBar
├── UserFilterBar
└── AdminUserList
    └── AdminUserListItem

AdminUserDetailPage
├── AccountSummaryCard
├── IdentitySummaryCard
└── AuthorizedActionPanel
    ├── PromoteDoctorDialog
    ├── ChangeDepartmentDialog
    ├── RevokeDoctorDialog
    └── AccountStatusDialog
```

- 页面容器负责接口调用、筛选、分页和缓存失效；
- 操作面板根据权限与服务端状态生成，不在多个列表组件重复判断；
- 展示组件只接收 props/emit，不直接调用 `uni.request`；
- 请求经过统一 API client，401 继续使用全局单次刷新机制；
- 用户详情以稳定 `account_id` 路由和查询，不使用姓名或手机号作为 ID。

## 5. 页面状态

- 首屏加载、下拉刷新、分页加载和没有更多；
- 搜索无结果、筛选无结果和后端失败重试；
- 用户在打开详情后被其他管理员修改产生的版本冲突；
- 当前管理员权限被撤销后的 `403` 和页面退出；
- 写操作提交中、校验失败、幂等重试和成功刷新；
- 当前目标账号已禁用、已撤销医生身份或已调岗时重新读取最新状态。

## 6. 验收标准

- 医生和普通用户无法看到入口，也不能直接打开用户管理页面；
- 超级管理员底栏仍为四项，从部门管理右上角进入用户管理；
- 用户列表和详情全部由后端分页、动态返回，无静态账号数据；
- 列表保持紧凑，所有高风险操作只出现在用户详情；
- 普通用户可被开通为医生，医生可调岗或撤销身份；
- 撤销医生身份后账号仍能作为普通用户使用；
- 禁用账号后患者端和工作人员端都不能继续登录；
- 恢复账号不会自动恢复已经撤销的医生身份；未撤销医生身份的禁用账号恢复后仍是医生；
- 超级管理员身份首版不可在该页面新增、撤销或禁用；
- 调岗、撤销身份、禁用账号均具有独立确认文案、权限校验、审计和缓存失效行为。
