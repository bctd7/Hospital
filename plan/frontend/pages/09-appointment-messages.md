# 预约消息页面

> 状态：待实施，当前只确认页面位置、消息范围和科室上下文；具体 UI 效果待后续讨论。
>
> 本页面沿用现有四 Tab 结构，第三栏继续为“消息”，不改变首页、医生名录/人员管理和“我的”的位置。

## 1. 患者端

患者消息页只展示本人预约产生的四类消息：

- 预约成功；
- 最晚到院时间前 1 小时和前 30 分钟的到院提醒；
- 正式检查报告发布；
- 正式检查报告更正。

预约成功和到院提醒进入现有“我的预约”详情；报告发布和报告更正进入现有报告详情。页面不增加其他未经确认的
消息类型。

## 2. 工作人员端

工作人员消息页只展示当前科室产生的三类消息：

- 新预约；
- 预约取消或未到场；
- 检查中但报告尚未完成。

工作人员从消息进入现有科室预约详情或报告填写页面。消息不分配给具体医生，也不增加执行医生选择。

## 3. 科室上下文

消息页顶部保留“当前范围”位置，按“院区 / 科室”显示当前科室。

- 医生：显示本人所属科室，不提供切换入口；
- 管理员：可以从消息页顶部切换院区和科室；
- 管理员优先沿用工作人员管理页面当前选择的科室，其次恢复上一次选择的科室；
- 管理员没有任何历史选择时，第一次进入消息页先选择科室，不自动选择第一个科室；
- 管理员不默认查看全院全部消息；
- 管理员可以在科室选择范围中知道各科室的未读数量，底部消息角标表示其可管理范围内的未读总数。

## 4. 已读与未读

- 患者和工作人员均按当前账号记录各自的消息已读状态；
- 点击消息进入对应详情时，将该消息标记为已读；
- 同一条科室消息由每位工作人员分别阅读，互不影响；
- 患者底部消息角标使用本人未读数量；
- 医生底部消息角标使用本科室中本人未读数量；
- 管理员底部消息角标使用其可管理科室中本人的未读总数，科室选择范围展示各科室未读数量。

## 5. 暂不确定的 UI

以下视觉和交互细节留待后续确认，本 Plan 不预设实现：

- 消息卡片样式、信息层级和留白；
- 当前范围选择器的具体展开形式；
- “待处理 / 全部”等页面内筛选是否保留；
- 已读和未读的具体视觉效果、空状态和动效。

## 6. 验收标准

- 第三栏仍然是消息，不改变现有四 Tab 页面结构；
- 患者和工作人员只展示已经确认的消息类型；
- 医生固定本科室，管理员在明确选择的科室范围内查看消息；
- 管理员首次进入时不会被系统随机指定科室；
- 每个账号独立记录已读状态，工作人员互不影响；
- 底部消息角标和管理员科室未读数量使用当前账号的未读统计；
- 页面不增加项目配置、规则编辑、医生筛选或新的工作台入口；
- 未确认的视觉细节不作为当前实施事实。
