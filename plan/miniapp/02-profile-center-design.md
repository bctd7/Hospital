# “我的”与就诊人管理静态页面设计

> 文档状态：历史静态方案，已被 `03-entry-and-profile-requirements.md` 取代
>
> 适用阶段：不接入后端的个人中心布局
>
> 参考界面：用户提供的蓝色个人中心菜单页

## 1. 本阶段目标

在现有“首页 / 挂号 / 消息 / 我的”应用外壳中完成“我的”页面及其静态二级页面，使页面可以在微信开发者工具中展示和跳转，但不读取账号、预约或关注数据。

本阶段包含：

- 蓝色装饰头部；
- 就诊人管理；
- 我的预约；
- 我的关注；
- 设置；
- 四个入口对应的静态二级页面；
- 可复用的菜单、信息列表和空状态组件。

明确排除：

- 候补订单；
- 消息管理；
- 独立身份验证页面、按钮或状态提示；
- 用户姓名、头像和真实就诊人数据；
- 预约、关注和设置接口；
- 任何模拟后端请求。

## 2. 身份信息边界

“我的”首页不展示用户姓名、头像、身份验证按钮或账号设置入口。页面头部只表达“个人中心”这一功能语义，避免未来身份状态在多个页面重复维护。

身份验证与姓名展示由“就诊人管理”页面后续单独设计，当前版本不提供相关界面。现阶段页面结构为：

```text
我的
  -> 就诊人管理
       -> 默认就诊人
       -> 家庭就诊人
```

当前只展示就诊人列表的静态空状态，不伪造用户身份、姓名或医疗数据。

## 3. 页面与路由

| 页面 | 路由 | 当前内容 |
|---|---|---|
| 我的 | `pages/profile/index` | 蓝色头部与四个功能入口 |
| 就诊人管理 | `pages/profile/patients/index` | 就诊人静态状态，不含身份验证界面 |
| 我的预约 | `pages/profile/appointments/index` | 空状态 |
| 我的关注 | `pages/profile/favorites/index` | 空状态 |
| 设置 | `pages/profile/settings/index` | 清除缓存、联系客服、隐私协议、账号注销的静态说明 |

二级页面使用普通页面导航，不加入底部 TabBar。

## 4. 组件边界

```text
components/profile/ProfileHero.vue
  负责蓝色装饰头部，不包含账号数据

components/menu/ActionMenu.vue
  根据 MenuEntry 数组渲染菜单并向外发出选择事件

components/menu/ActionMenuItem.vue
  负责单行图标、标题、说明、箭头和点击反馈

components/info/InfoList.vue
  根据 InfoRow 数组渲染静态信息卡片

types/menu.ts
  统一菜单色调、入口和信息行类型
```

页面只维护菜单配置和路由响应，不复制菜单行的结构与样式。未来增加入口时优先修改数据配置；只有布局语义发生变化时才修改组件。

## 5. 视觉规则

- 头部使用蓝色渐变和抽象波形，不使用真实头像；
- 内容背景使用浅灰蓝，菜单卡片使用白色；
- 每个入口使用单字符符号和固定色调，不依赖网络图标；
- 标题、说明和右侧箭头保持统一对齐；
- 长说明单行截断，完整内容在对应二级页表达；
- 适配微信状态栏和底部原生 TabBar；
- 不照搬参考图中的姓名、头像和品牌素材。

## 6. 后端边界

本阶段不新增或修改任何 API 契约，不访问：

- 身份验证接口；
- 就诊人接口；
- 预约接口；
- 关注接口；
- 消息接口；
- 用户配置接口。

页面数据均为源码中的结构化静态配置。未来接入后端时，菜单结构仍由前端维护，只有页面内容和状态由对应 Store/API 模块提供。

## 7. 验收标准

- “我的”页不出现姓名、头像、身份验证按钮；
- 页面只显示就诊人管理、我的预约、我的关注、设置；
- 不出现候补订单和消息管理；
- 四个入口均可打开对应的二级页面；
- 二级页面均可正常返回“我的”；
- 当前工程不存在独立身份验证页面、路由、入口或状态占位；
- 身份验证和姓名展示留待就诊人管理页面的后续专项设计；
- 页面切换不发起网络请求；
- 布局在普通屏幕和全面屏下不被状态栏或 TabBar 遮挡；
- TypeScript 检查和微信小程序构建通过。
